### ① 美擴大 AI 晶片出口管制，阿里子公司列實體清單

美國商務部工業與安全局（BIS）11 月 24 日公布出口管制新規，以先進運算產品違規轉供風險為由，將 Megaspeed 及阿里巴巴旗下新加坡子公司等 7 家東南亞公司列入實體清單。馬來西亞政府同日宣布，將通知境內資料中心業者建議不要對列名公司提供服務。此舉顯示美方正把防線從晶片原廠延伸到第三地的算力轉售與資料中心環節。

### ② Google 推出 AI 代理人安全控管介面

Google 週二（11 月 24 日）公布一組專門的 AI 代理人控管介面，以現代化的建構工具與介面，提供企業對代理人活動的可視度與控管。隨著 AI 代理人開始代替使用者存取資料、執行任務，資料與隱私風險成為企業導入時的主要顧慮。這套介面等於把代理人治理從口號變成可操作的基礎設施。

| 面向 | 說明 |
| :-- | :-- |

### ③ Tidal 12/9 起全面封殺純 AI 生成音樂

| 面向 | 說明 |
| :-- | :-- |
| **📌 事件** | Tidal 於 11 月 24 日宣布，12 月 9 日起拒收完全由 AI 生成的音樂，並下架平臺上既有的純 AI 歌曲。 |
| **🧭 背景** | Tidal 自 2014 年推出以來強調創作者收益與無損音質，2015 年被 Jay-Z 收購、2021 年由 Block 取得多數股權，政策方向一向偏向保障創作者。 |

| **🧭 背景** | 愈來愈多公務人員主動用生成式 AI 撰寫文件、整理資料、查詢法規，單純禁止既擋不住使用，也會錯失行政效率提升的機會。 |

### ⑥ safe-anything：Rust 寫的高速漏洞掃描器

GitHub 新興專案 safe-anything 以 100% Rust 實作，主打快速找出 XSS、SQL injection、外洩密鑰、依賴套件 CVE，甚至涵蓋 AI agent 的設定檢查。專案目前已累積約 687 顆星。在 AI agent 大量接入系統的當下，把 agent 設定納入掃描範圍是它較特別的地方。

| 面向 | 說明 |
| :-- | :-- |
| **🎯 問題** | 開發團隊常在漏洞被外部發現後才補救，需要一個能在上線前快速掃出常見風險的工具。 |
| **⚙️ 方法** | 以純 Rust 實作高速掃描引擎，涵蓋 XSS、SQL injection、外洩密鑰、依賴套件 CVE，並延伸檢查 AI agent 的設定。 |
| **🚀 用法** | 可直接從 GitHub 取得開源專案（erkamyaman/safe-anything）使用。 |
| **✨ 優勢** | Rust 帶來執行速度優勢，且單一工具同時涵蓋程式碼、依賴與 AI agent 設定三種風險面。 |

### ⑦ PiBot：本地優先的桌面多代理 AI 團隊

### ⑧ 用可驗證信念獎勵，治好長任務代理的偷懶

研究指出，AI 代理在處理長任務時常在意見尚未收斂前就提前給出答案，這種行為被稱為「偷懶」，即使它陳述的信念仍列出多個可能答案。由於現行做法只在任務結束時對最終答案給出結果獎勵，無法教會代理「何時該承諾」。團隊因此提出以可驗證信念為訊號的強化學習方法。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 長任務代理常在證據不足時就提前承諾答案，而僅依最終答案給分的結果獎勵無法教會它判斷何時該下定論。 |
| **💡 核心方法** | 以「可驗證的信念」作為強化學習的獎勵依據，讓代理依自己實際相信的內容行動，而非提早鎖定答案。 |
| **📊 成果** | 原文未提供具體數據，僅指出在評估中代理經常在信念仍有多個可能答案時就提前承諾。 |
| **🛠️ 實務意義** | 對長流程 agent 的訓練提供了新的獎勵設計方向，但前提是系統能取得可驗證的信念表示。 |

### ⑨ 一面鏡子就讓機器人操作策略失效

研究團隊受動物認知中的鏡子自我辨識實驗啟發，檢驗機器人操作策略在含鏡像反射的場景中，是否還能可靠地操作實體物件。他們建構 RoboDojo-Mirror 基準，在保留原任務設定的前提下加入鏡子反射情境。結果顯示，一面簡單的鏡子就足以讓現有策略失效。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 現有機器人操作策略的評測多半在無反射干擾的場景進行，無法反映真實環境中鏡面、玻璃造成的視覺混淆。 |
| **💡 核心方法** | 建構 RoboDojo-Mirror 基準，在保留 RoboDojo 原任務設定的條件下加入鏡子反射，系統性檢驗策略的穩健性。 |
| **📊 成果** | 原文未提供具體數據，但研究結論指出簡單的鏡子就能讓現有機器人操作策略失敗。 |
| **🛠️ 實務意義** | 對準備把機器人部署到醫院、零售等充滿反射面場域的團隊是一記警訊；限制在於目前驗證仍以模擬基準為主。 |

🔗 [閱讀原文](https://huggingface.co/papers/2611.33010)　·　`Hugging Face Daily Papers`

### ⑩ QDA：讓 AI 代理自動設計量化配方

MIT 與 NVIDIA 的研究團隊提出 QDA，讓一個代理針對每個模型與精度組合，自動設計後訓練量化（PTQ）配方。系統以代理從未見過的推理軌跡上、相對原始模型的輸出 KL 散度作為評分依據，幾分鐘內就能篩選候選配方，並可调用共享的公開 PTQ 方法庫。這把量化調校從人工試錯變成可自動化的搜尋流程。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 後訓練量化需要針對不同模型與精度逐一調整配方，人工搜尋成本高且難以規模化。 |
| **💡 核心方法** | 由代理自動設計量化配方，並以模型在未見過的推理軌跡上、輸出分佈相對原模型的 KL 散度快速評分，同時共用公開 PTQ 方法庫。 |
| **📊 成果** | 研究在四項推理相關評測上驗證；原文未提供具體數據。 |
| **🛠️ 實務意義** | 可降低模型壓縮與部署的調校門檻，但評分依賴 KL 散度這類代理指標，與實際任務表現的落差仍需驗證。 |

🔗 [閱讀原文](https://academy.dair.ai/papers/qda-closed-loop-llm-quantization-design-with-agents-2611.23388)　·　`dair-ai 每週精選論文`
