## 🛠️ AI 新工具

### ⑥ opengame 把 coding agent 變成遊戲工作室

GitHub 專案 opengame 以「AI agent 的 Unity 與 Unreal」為定位，內建 100 多款可改編的遊戲模板，並可串接 Claude Code、Codex、DeepSeek 等 20 多種 coding agent。目標是把單一代理升級成能建置、發布遊戲的完整工作室。

| 面向 | 說明 |
| :-- | :-- |
| **🎯 問題** | 開發者想用 coding agent 做遊戲，但從企劃、建置到跨平台發布的流程零散，難以串成可重複的工作流。 |
| **⚙️ 方法** | 提供 100 多款可 remix 的遊戲模板作為起點，再把 20 多種 coding agent 接入同一套建置與發布管線。 |
| **🚀 用法** | 從 GitHub 取得專案，挑選模板並指定慣用的 coding agent，即可建置 3D 或小遊戲並發布到微信、抖音、TikTok、Telegram、itch.io 等平台。 |
| **✨ 優勢** | 把遊戲開發到上架的多個環節自動化，讓個人開發者能快速驗證玩法點子並直接觸及多個通路的用戶。 |

🔗 [閱讀原文](https://github.com/nexu-io/opengame)　·　`GitHub 新興專案`

| **🚀 用法** | 從 GitHub 取得 skill，掛載到既有的 coding agent 工作流程中使用。 |
| **✨ 優勢** | 把驗證往前移到生成階段，可減少後續人工審查與線上除錯的成本。 |

| **🚀 用法** | 下載對應平台的 binary 直接執行，透過內建的網頁儀表板操作與監看。 |
| **✨ 優勢** | 免安裝依賴即可在本地推論，並以投機解碼換取生成速度，適合快速部署到各種機器。 |

### ⑪ Harness 自我改進 需要一份可遷移的記憶

Google Cloud AI、DeepMind 與賓州州立大學的研究指出，harness 最佳化通常綁定單一模型與單一 benchmark，一旦換模型或換任務，優化器就難以判斷哪些改動該保留。問題在於 harness 程式碼本身沒有記錄「為何改、效果如何」。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 現有 harness 最佳化多在固定模型與固定 benchmark 下進行，換模型或換任務後，優化器無法判斷哪些既有改動仍值得保留。 |
| **💡 核心方法** | 研究讓 harness 的演化過程保留可重用的記憶，把每次編輯的理由與實際表現一併記錄下來，作為跨模型、跨 benchmark 遷移的依據。 |
| **📊 成果** | 原文未提供具體數據。 |
| **🛠️ 實務意義** | 對自行調校 agent harness 的團隊，可望省下換模型後重跑整輪搜尋的成本；限制在於記憶本身的維護與檢索品質。 |

### ⑫ GUARD 讓自我改寫的代理不再越改越差

Google Cloud 研究者指出，沒有外部評分器把關、自行改寫 harness 的代理往往越改越差。反思與純量分數會把「這次改壞了什麼」和「本來就沒解決的問題」混在一起，導致局部退步、技能遺忘與記憶膨脹。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 自我改寫 harness 的代理缺乏外部評分訊號時，容易把新引入的破壞誤判為進步，長期下來出現局部退步、技能遺忘與記憶膨脹。 |
| **💡 核心方法** | GUARD 是一個演化 prompt、skill、tool 等 harness 元件的框架，透過外部評分區分「這次改動新弄壞的部分」與「原本就存在的缺陷」。 |
| **📊 成果** | 原文未提供具體數據。 |
| **🛠️ 實務意義** | 可讓長期自我改進的代理不至於退化，實務上需先建立可靠的評分訊號，否則框架效果受限。 |

🔗 [閱讀原文](https://academy.dair.ai/papers/guard-stabilizing-recursive-self-improvement-with-regret-guidance-2611.23476)　·　`dair-ai 每週精選論文`

### ⑬ EfficientSkill 先求準再剪枝 壓低 token

Google 與普渡大學的研究觀察到，技能優化器習慣在每次失敗後新增一條規則，技能越長、代理每輪讀的 token 越多，長流程就開始逾時。EfficientSkill 改為先以準確率為目標學習技能，再針對長度進行剪枝。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 現有技能優化器每失敗一次就加一條規則，技能持續膨脹，代理每回合讀取的 token 增加，長流程容易逾時。 |
| **💡 核心方法** | EfficientSkill 把學習拆成兩階段：先以準確率為目標把技能學好，再針對長度做剪枝壓縮。 |
| **📊 成果** | 原文未提供具體數據。 |
| **🛠️ 實務意義** | 對長時程代理可直接降低 token 成本與延遲；限制是剪枝可能誤刪只在罕見情境才需要的規則。 |

🔗 [閱讀原文](https://academy.dair.ai/papers/efficientskill-learning-skills-for-token-efficient-multi-turn-agents-2611.19823)　·　`dair-ai 每週精選論文`

### ⑭ Safe Personal RSI 為個人助理更新設閘門

CMU、UCSD、UC Berkeley 等機構的研究指出，改動個人助理的指令雖能提升任務表現，卻同時改變它揭露什麼資訊、遵循哪些請求、如何回報行動。團隊因此打造 Safe Personal RSI，為個人健康助理 Kicker 加上更新閘門。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 個人助理的指令一旦更新，任務表現與安全屬性會同時改變，包括揭露範圍、遵循哪些請求與行動回報方式，現有流程難以一起評估。 |
| **💡 核心方法** | 提出 Safe Personal RSI，在採納指令更新前先經過一道閘門，檢查更新對安全相關行為的影響。 |
| **📊 成果** | 原文未提供具體數據。 |
| **🛠️ 實務意義** | 為個人化助理的持續自我改進提供把關機制；限制是閘門必須涵蓋足夠多的安全面向，否則可能放行有風險的更新。 |

🔗 [閱讀原文](https://academy.dair.ai/papers/safe-personal-rsi-evaluating-and-repairing-personal-agent-updates-2611.23651)　·　`dair-ai 每週精選論文`
