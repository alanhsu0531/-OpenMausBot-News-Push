### ② 42 州檢察長聯手阻擋 Character.AI 賣對話

美國 42 州檢察長同步發出聲明，要求阻止 Character.AI 在 Chapter 11 破產程序中拍賣超過 2,100 萬個美國帳號的私人對話紀錄。AI 陪伴服務累積大量帶有情感揭露的對話，破產後被視為可變現資產，引發州層級的高度警戒。這起案件將直接測試「聊天紀錄能不能當資產賣」的界線。

| 面向 | 說明 |

| **🧭 背景** | Character.AI 長期提供角色陪伴對話，累積大量青少年與成年用戶的私密內容，進入破產程序後資料成為清償資產的一部分。 |

## 🛠️ AI 新工具

### ⑤ 純組合語言跑 Qwen3-0.6B，推論僅 12KB

GitHub 專案 llm.asm 用純 x86-64 NASM 組合語言實作 Qwen3-0.6B 推論（12KB）、可開機的裸機作業系統（22KB），以及搭配盲文 TUI 的 Mini-GPT 訓練器（32KB）。整個專案零 C、零 libc、零外部相依。對想理解模型推論最小可行實作的人來說，這是一份難得的教材。

| 面向 | 說明 |
| :-- | :-- |
| **🎯 問題** | 多數 LLM 推論框架依賴龐大的執行環境與相依套件，難以看清推論在機器層級到底做了什麼。 |
| **⚙️ 方法** | 全部以 x86-64 NASM 組合語言手寫，包含 Qwen3-0.6B 推論、可直接開機的裸機 OS，以及從零實作的 Mini-GPT 訓練器與盲文 TUI。 |
| **🚀 用法** | 從 GitHub 取得原始碼，以 NASM 組譯後在 x86-64 實機或虛擬機開機執行，需自行準備模型權重。 |
| **✨ 優勢** | 體積與相依幾乎歸零，適合裸機、嵌入式與作業系統教學，也讓推論流程的每一步都可被逐行檢視。 |

🔗 [閱讀原文](https://github.com/alesha-pro/llm.asm)　·　`GitHub 新興專案`

### ⑥ shrink-anything：測試過才刪死碼

shrink-anything 針對程式碼庫長期累積的死碼、冗餘檔案、相依與資源，提出「刪了再驗」的自動化流程。每次刪減後都會重跑使用者自己的測試，只有測試仍全數通過才保留該次刪減。等於用團隊既有的測試當安全網，換取更精簡的程式碼庫。

| 面向 | 說明 |
| :-- | :-- |
| **🎯 問題** | 專案越長越大，死碼與沒人用的相依不斷累積，人工清理風險高又耗時，多數團隊乾脆放著不管。 |
| **⚙️ 方法** | 自動找出可刪除的程式碼、檔案、相依與資源，逐一刪減後重跑使用者自己的測試套件，測試沒過就回退。 |
| **🚀 用法** | 從 GitHub 取得腳本，在專案根目錄執行，前提是專案已有可信任的測試作為驗證依據。 |
| **✨ 優勢** | 判斷標準是團隊自己的測試而非通用規則，能在不改變行為的前提下縮減程式碼量，降低維護與建置成本。 |

🔗 [閱讀原文](https://github.com/EL4CTEO/shrink-anything)　·　`GitHub 新興專案`

### ⑦ sap-data-mcp：AI 唯讀查詢 SAP

sap-data-mcp 提供一組唯讀的 MCP 伺服器，讓 AI 助理能透過 RFC/BAPI、私有雲 OData 與公有雲已釋出的 API 查詢 SAP S/4HANA。每次呼叫都會留下稽核紀錄，憑證則保留在本地端。對想把 ERP 資料接上代理式工作流、又不敢開放寫入權限的企業來說，這是相對保守的起點。

| 面向 | 說明 |
| :-- | :-- |
| **🎯 問題** | 企業想讓 AI 助理取用 ERP 內的訂單、庫存與主檔資料，但直接給予寫入權限的風險過高。 |
| **⚙️ 方法** | 以唯讀 MCP 伺服器封裝 SAP 查詢介面，支援 RFC/BAPI、私有雲 OData 與公有雲 API，並對每次呼叫留下稽核軌跡。 |
| **🚀 用法** | 部署 MCP server、設定 SAP 連線與本地憑證，再於支援 MCP 的 AI 助理或代理框架中掛載使用。 |
| **✨ 優勢** | 以唯讀與稽核設計降低導入風險，讓既有 ERP 資料能接上代理工作流，同時保留權限與責任的界線。 |

🔗 [閱讀原文](https://github.com/w1ccc/sap-data-mcp)　·　`GitHub 新興專案`

### ⑧ iWSP：讓 LLM 直接寫出模型權重

微軟研究院與合作者提出可解釋權重空間程式設計（iWSP），讓 LLM 代理用寫程式的方式，直接產生模型權重與特徵，而不是只調整超參數或架構。如此一來，模型的行為可以用可讀的程式碼表達，補上深度模型「預測準但說不清為什麼」的缺口。對需要解釋性的科學應用特別有吸引力。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 深度模型預測能力強，但在科學場景中往往需要說明哪些特徵驅動預測，現有模型難以提供這種解釋。 |
| **💡 核心方法** | 讓 LLM 代理以程式碼直接撰寫模型權重與特徵，把建模變成一種可閱讀、可檢查的權重空間程式設計。 |
| **📊 成果** | 原文未提供具體數據。 |
| **🛠️ 實務意義** | 對需要可解釋模型的科學與醫療場景有吸引力，但 LLM 產生權重的穩定性、可規模化程度與正確性驗證仍是限制。 |

### ⑨ AutoRL：多代理即時監督 RL 訓練

美團與合作大學提出 AutoRL，用多代理系統即時監督正在進行的強化學習訓練，模擬人類研究者觀察曲線、判斷問題、調整設定的過程，而不是套用固定配方。這針對的是 RL 訓練不穩定、需要大量人工盯場的老問題。若能穩定運作，將降低 RL 的人力門檻。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 強化學習是提升模型能力的關鍵步驟，但訓練不穩定、需要持續人工監督，導致自動化難以落地。 |
| **💡 核心方法** | 以多代理系統分工扮演 RL 研究者的角色，在訓練過程中即時監控與調整，而非依賴事先寫死的固定配方。 |
| **📊 成果** | 原文未提供具體數據。 |
| **🛠️ 實務意義** | 可望降低 RL 訓練的人力成本，但多代理監督本身會增加系統複雜度與推論開銷，實際部署仍需成本效益評估。 |

🔗 [閱讀原文](https://academy.dair.ai/papers/autorl-a-multi-agent-system-towards-autonomous-reinforcement-learning-2611.17790)　·　`dair-ai 每週精選論文`

### ⑩ Meta 質疑最大似然：常見不等於為真

Meta 這篇評論文章直指 LLM 的主流訓練原則最大似然，既不是真理的必要條件也不是充分條件：罕見事件天天發生，而被反覆複述的語句也可能是錯的。文章借用 Nozick、Poincaré、Cassirer 等把客觀性連結到「不變性」的哲學觀點，主張改用對變化的穩健程度來判斷。這是對當前預訓練目標少見的正面挑戰。

| 面向 | 說明 |
| :-- | :-- |
| **🧩 問題** | 最大似然是 LLM 訓練的主流目標，但語料中常見的說法未必為真、真實發生的事件也未必常見，似然高低與真實性之間存在落差。 |
| **💡 核心方法** | 援引把客觀性定義為「對變化的不變性」的哲學傳統，主張以模型結論在擾動與不同情境下是否穩定，作為判準。 |
